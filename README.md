# Бот записи клиентов — готовый шаблон

Telegram-бот для студии, салона, мастера или консультаций. Python 3.12+,
aiogram 3, SQLite; отдельный сервер базы данных не нужен.

## Что умеет

**Клиент:** кнопки → услуга → специалист → дата → свободное время → имя и
телефон → подтверждение. Просмотр своих записей, отмена с подтверждением,
напоминание о визите, FAQ и контакты. Часы всегда показываются в часовом поясе бизнеса.

**Администратор:** уведомления о новых записях и отменах с контактами клиента,
записи на сегодня/завтра и все будущие записи с пагинацией, отмена с уведомлением
клиента, количество будущих записей и клиентов, экспорт CSV, закрытие отдельных дней.

**Расписание:** несколько сотрудников, разные услуги и длительности, общая или
индивидуальная рабочая неделя, перерывы, выходные и праздничные даты.
Занятые интервалы исключаются с учётом всей длительности услуги. Запись повторно
проверяется при подтверждении, SQLite-транзакция защищает от одновременной записи
двух клиентов. Один клиент не может записаться к разным сотрудникам на одно время.

## Быстрый запуск

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
cp .env.example .env
chmod 600 .env
```

Откройте `.env` и заполните:

- `BOT_TOKEN` — токен нового бота от **@BotFather**;
- `ADMIN_IDS` — ваш числовой Telegram ID; несколько через запятую;
- `CONFIG_PATH` и `DATABASE_PATH` можно оставить как в примере.

Если не знаете ID, оставьте `ADMIN_IDS` пустым, запустите бота и отправьте ему `/id`.
Впишите полученное число, перезапустите бота. Администраторам нужно сначала открыть
бота и нажать `/start`, чтобы Telegram разрешил отправлять им уведомления.
Токен не отправляйте в чат, не коммитьте `.env` в Git.

Отредактируйте **[config.yaml](config.yaml)** под свой бизнес, затем:

```sh
.venv/bin/python -m booking_bot --check
.venv/bin/python -m booking_bot
```

`--check` проверяет настройки, открывает/создаёт базу и собирает обработчики
**без обращения к Telegram**. Для реального запуска нужен HTTPS-доступ к
`api.telegram.org` и настоящий токен. Один бот/токен — один polling-процесс.
Если этот токен раньше использовал webhook, удалите webhook через Telegram Bot API
перед запуском polling. Бот сам webhook не удаляет, чтобы не затронуть другую установку.

## Где менять настройки

| Настройка | Место |
| --- | --- |
| Название, приветствие, адрес, контакты, валюта | `business` в `config.yaml` |
| Часовой пояс | `business.timezone`, например `Asia/Bishkek`, `Europe/Moscow` |
| Услуги, стоимость, длительность | `services` |
| Сотрудники и доступные им услуги | `staff` |
| Рабочая неделя, перерывы | `schedule`: 0 — пн, 6 — вс; `[]` — выходной |
| Индивидуальная неделя сотрудника | `staff[].schedule` полностью заменяет общую неделю |
| Праздники и отпуск | `booking.closed_dates` и `staff[].closed_dates` |
| Горизонт записи, шаг времени, минимальное время до визита | `booking` |
| Напоминание и срок самостоятельной отмены | `reminder_minutes`, `cancel_notice_minutes` |
| Максимум будущих записей клиента | `max_active_per_client` |
| Вопросы и ответы | `faq` |
| Администраторы и токен | `.env`; после изменения перезапустите процесс |

ID услуг/сотрудников — постоянные ключи из латинских строчных букв, цифр и `_`
(до 16 символов). После изменения YAML отправьте `/reload` от администратора
или перезапустите бота. При ошибке `/reload` сохраняет текущие настройки.
Существующие записи хранят названия, цену, сотрудника и длительность на момент записи.
Изменение расписания и удаление услуги не отменяют старые записи автоматически.
Часовой пояс и валюту желательно задать до начала работы: валюта в сообщениях
берётся из актуального конфига. Изменения из `.env` требуют перезапуска.
Настройки редактируются в файле; Telegram-меню предназначено для управления записями.

## Команды

Клиент: `/start`, `/menu`, `/mine`, `/id`. Запись и отмена — через кнопки.
Отмена снимает бронь и оставляет запись в истории базы.
Старая текстовая команда `/book ДАТА ВРЕМЯ` заменена пошаговой записью.
Работа с клиентскими данными доступна только в личном чате с ботом.

Администратор:

- `/admin` — управление, статистика и выгрузка CSV будущих активных записей;
- `/close 2027-01-01` — запретить новые записи на дату;
- `/open 2027-01-01` — снять блокировку, созданную через `/close`;
- `/reload` — перечитать настройки бизнеса.

`/open` не отменяет выходные и отпуск в YAML. Закрытие дня **не отменяет уже
созданные записи**: их видно в админ-меню, отменяйте отдельно с уведомлением клиента.
Администратор может отменить запись без ограничения срока отмены.

## Развёртывание с systemd

На сервере нужны Linux с systemd, Git, Python 3.12+ и модуль venv.
Пример для новой установки (команды от root):

```sh
git clone https://github.com/baimovy03-dev/pss.git /opt/booking-bot
cd /opt/booking-bot
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
id bookingbot >/dev/null 2>&1 || useradd --system --home /opt/booking-bot --shell /usr/sbin/nologin bookingbot
# Только каталог проекта, не .env: секреты сервера находятся отдельно в /etc.
chmod 755 /opt/booking-bot
find booking_bot .venv -type d -exec chmod a+rx {} +
find booking_bot .venv -type f -exec chmod a+r {} +
chmod 644 config.yaml
# Не очищает файл, если он уже существует.
touch /etc/booking-bot.env
chmod 600 /etc/booking-bot.env
```

Отредактируйте `/etc/booking-bot.env`:

```dotenv
BOT_TOKEN=ВАШ_ТОКЕН
ADMIN_IDS=ВАШ_ID
CONFIG_PATH=/opt/booking-bot/config.yaml
```

Затем настройте `/opt/booking-bot/config.yaml` и установите службу:

```sh
cp deploy/booking-bot.service /etc/systemd/system/booking-bot.service
systemctl daemon-reload
systemctl enable --now booking-bot
systemctl status booking-bot
journalctl -u booking-bot -n 50 --no-pager
```

Служба запускается непривилегированным пользователем `bookingbot`. systemd
создаёт `/var/lib/booking-bot` с правами для базы. Секреты читает systemd из
`/etc/booking-bot.env`. Код и config.yaml доступны боту только на чтение.
Не копируйте локальный `.env` в каталог серверной установки.
Проверить синтаксис службы на целевом сервере:
`systemd-analyze verify /etc/systemd/system/booking-bot.service`.
Служба подготовлена, но не устанавливалась на ваш сервер из этой среды.

Обновление: остановите службу, сделайте резервную копию базы и своего конфига,
обновите код, установите `requirements.lock`, проверьте настройки, запустите службу.
Для отдельного бизнеса используйте **отдельный токен, конфиг, базу и службу**;
если бизнесов несколько, скопируйте unit и измените пути и `StateDirectory`.

## Тесты и проверка перед использованием

```sh
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m pip check
.venv/bin/python -m booking_bot --check
```

Тесты проверяют расписание и перерывы, конкурентные бронирования, отмену,
ограничения, миграцию старой демо-базы и полный сценарий обработчиков через
имитацию Telegram API. Они не используют настоящий токен и не отправляют сообщения.

Живая проверка после запуска:

1. В Telegram нажмите `/start`, создайте запись и проверьте «Мои записи».
2. Другим клиентом попробуйте занять то же время; оно не должно быть доступно.
3. В админ-меню проверьте запись, контакт, CSV и закрытие будущего дня.
4. Отмените запись клиентом или администратором, проверьте уведомление и освобождение времени.
5. Создайте запись в пределах `reminder_minutes`, дождитесь напоминания;
   для короткой проверки временно уменьшите `min_notice_minutes` до 0.

В облачной среде доступ к Telegram ранее блокировался сетевым прокси (403).
Живые сообщения, доставка напоминаний и ваша systemd-установка требуют проверки
с вашим токеном на целевом сервере.

## Данные и эксплуатация

Данные остаются в SQLite. Старые записи первой версии демо импортируются один раз
в новую таблицу, исходная таблица сохраняется. Старый визит временно блокирует
всех специалистов, пока не завершится или не будет отменён администратором.
Перед обновлением всегда делайте резервную копию.

Резервная копия через стандартный SQLite backup API, в доступный защищённый каталог:

```sh
python3 - <<'PY'
import sqlite3
from pathlib import Path
from contextlib import closing
source = Path('/var/lib/booking-bot/bookings.sqlite3')
if not source.is_file():
    raise SystemExit('База не найдена: проверьте путь')
with closing(sqlite3.connect(source)) as src, closing(sqlite3.connect('/root/booking-backup.sqlite3')) as dst:
    src.backup(dst)
PY
chmod 600 /root/booking-backup.sqlite3
```

База и CSV содержат имена, телефоны и Telegram ID. Ограничьте доступ и определите
срок хранения для своего бизнеса. Автоматического удаления старых записей нет.
Не включайте токен в архив исходников. Не выставляйте SQLite в публичный доступ.

Напоминания восстанавливаются из базы при перезапуске, но прошедшие визиты
не напоминаются. После успешной отправки ставится отметка; если процесс упал между
отправкой и сохранением, возможно повторное сообщение. Если клиент заблокировал
бота, повторные попытки для этого напоминания прекращаются. Ошибки Telegram
повторяются через 30 секунд. Админ-уведомления отправляются сразу, без постоянной
очереди повторной доставки; при сетевом сбое ориентируйтесь на список записей.
Незавершённые шаги формы при перезапуске сбрасываются, подтверждённые записи сохраняются.
При переводе часов неоднозначные слоты используют первое вхождение; переход через
смену смещения и несуществующее местное время не предлагаются.

Шаблон не включает платежи, CRM-интеграции и web-панель. Настройки бизнеса меняются
без изменения Python; интерфейс бота и дополнительные функции можно доработать отдельно.
